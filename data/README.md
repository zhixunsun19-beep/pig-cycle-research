# 数据目录（data/）

```
data/
├── processed/           # 可直接使用的结构化结果（推荐引用这一层）
│   ├── v3_results.json          # 评分/压力测试/弹性/四象限 —— 正式评分唯一来源
│   ├── v2_results.json          # v2 旧评分存档，仅历史对比，不可与 v3 互比
│   ├── derived_metrics.json     # 15 家三表衍生指标（有息负债、现金流、资本开支等）
│   ├── v1_data.json             # v1 研究数据层（成本/效率/事件/分部说明），compute 依赖
│   ├── v2_*.csv（9 个）          # 报告表格的直接来源
│   └── chart_data/*.csv（10 个） # 10 张图的制图源数据
├── raw/                 # 15 家 × 8 期财报三表原始科目（JSON）
└── metadata/            # 字典、公式、来源、期间、缺口
```

## 1. 先读哪几个

| 想核对 | 打开 |
|---|---|
| 评分、象限、阈值 | `processed/v3_results.json` |
| 报告的表格数字 | `processed/v2_*.csv` |
| 有息负债 / 现金流 / 资本开支 | `processed/derived_metrics.json` |
| 字段含义与单位 | `metadata/data_dictionary.md` |
| 公式与假设 | `metadata/formulas.md` |
| 来源与日期 | `metadata/source_register.md` |
| 数据缺口 | `metadata/missing_data.md` |

## 2. 文件名里的 `v2_` 是什么

9 个 CSV 的前缀 `v2_` 是**产出批次编号**（对应研究数据层 `research_data_v2.py`），**不是 v2 版评分**。评分版本以 `v3_results.json` 为准。报告正文引用的文件名保持不变，便于与正文逐条对应。

## 3. 使用这些数据必须知道的五件事

1. **v2 与 v3 不可混用。** v3 修复了 A2 与 A1 的重复计分（A2 改为仅一手现金成本），并把四象限阈值改为 7 家合格企业中位数。`v2_results.json` 仅供第 8 章新旧对比，分数不可直接比较。
2. **缺失不按 0。** 核心池 9 家 A2 现金成本全部未披露 → 整项未评分，生存维度有效满分 60→50（合格企业）或 35（待核实企业）。JSON 中 `score: null` 与 CSV 中 `—` 均表示缺失。
3. **成本期间不同。** 12 家可核实完全成本的数据期间横跨 2026-03 至 2026-10 及季度累计，**不是同一时点排名**；`metadata/source_periods.md` 逐家标注期间。
4. **集团 ≠ 业务。** 现金流与现金跑道均为上市公司集团口径；15 家均无分部现金流披露，养猪业务跑道标「无法独立测算」。
5. **理论增量 ≠ 预测。** `elasticity.csv`、`cash_runway_scenarios.csv`、`output_increase_10pct.csv` 均为静态敏感性测算（假设出栏量、均重、成本结构不变，不含税费），不是盈利预测。

## 4. `raw/` 的合规说明

`raw/*.json` 为 15 家 A 股公司 8 个报告期的资产负债表、利润表、现金流量表**原始科目**，通过新浪财经公开财报接口获取，对应交易所定期报告披露内容，不含付费数据库专有字段、不含个人信息。

- 用途：支撑 `derived_metrics.json` 的复算与数字追溯。
- 再分发：属公开披露的财务事实数据；若你所在场景对接口条款有额外要求，可**整体删除 `raw/`**，不影响 `processed/` 与报告阅读（仅影响从三表重算）。
- 详见 `docs/validation/publication_audit.md`。
